# Telegram-бот для автопостинга в каналы

Локальный бот, который с заданным интервалом отправляет одно и то же сообщение
во все выбранные Telegram-каналы. Отправка идёт от юзер-аккаунта через Telethon,
управление — через отдельного Telegram-бота с кнопками.

## Возможности

- 📋 список каналов редактируется прямо в чате (`@username`, `t.me/...` или числовой ID);
- ✏️ текст рассылки меняется через бота;
- ⏱ интервал: пресеты 15 / 30 / 60 / 120 минут или своё значение;
- ▶️/⏹ старт и стоп рассылки, старт блокируется при пустой конфигурации;
- бот отвечает только владельцу (`OWNER_ID`);
- логи в `logs/bot.log` с ротацией и хранением 14 дней.

## Настройка

1. Получите `API_ID` и `API_HASH` на https://my.telegram.org.
2. Создайте управляющего бота у [@BotFather](https://t.me/BotFather) и возьмите `BOT_TOKEN`.
3. Узнайте свой Telegram user id (например, у [@userinfobot](https://t.me/userinfobot)) — это `OWNER_ID`.
4. Скопируйте пример конфигурации и заполните его:

```bash
cp .env.example .env
```

`.env`, `data/` и `logs/` в git не попадают.

## Запуск локально

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
python bot/main.py
```

При первом запуске Telethon спросит номер телефона и код подтверждения —
дальше сессия переиспользуется из `data/session.session`.

Затем напишите управляющему боту `/start` и настройте рассылку кнопками.

## Запуск в Docker

Первый запуск — интерактивный, чтобы пройти авторизацию Telethon:

```bash
docker compose run --rm bot
```

После того как сессия создана в `data/`, бот поднимается в фоне:

```bash
docker compose up -d
```

`data/` и `logs/` смонтированы как volume, поэтому сессия, `state.json` и логи
переживают пересборку образа. После `docker compose restart` рассылка всегда
остановлена — запускать её нужно кнопкой «Старт».

## Код подтверждения не приходит

Диагностика — скрипт показывает, каким способом Telegram отправил код:

```bash
python scripts/check_auth.py
```

Частые причины:

1. **Номер не в международном формате.** Нужен `+79991234567`, а не `89991234567`.
2. **Код ушёл в приложение, а не в SMS.** Для сторонних клиентов Telegram почти
   всегда шлёт код сообщением в чат «Telegram» на уже авторизованном устройстве.
   Проверьте в том числе папку «Архив».
3. **К аккаунту привязан login email.** Тогда код уходит на почту
   (`SentCodeTypeEmailCode`), а в Telegram не приходит вообще.
4. **Авторизация с IP дата-центра.** Telegram часто не доставляет код, если
   новая сессия создаётся с серверного IP. Рабочий обходной путь — авторизоваться
   на домашнем компьютере и перенести готовую сессию на сервер:

   ```bash
   # локально, с тем же .env
   python scripts/check_auth.py   # или python bot/main.py, ввести код
   # затем скопировать сессию на сервер
   scp data/session.session user@server:/path/to/project/data/
   ```

   После этого на сервере достаточно `docker compose up -d` — код больше не спросят.
   `API_ID` и `API_HASH` на сервере должны быть те же, что при авторизации, и одну
   сессию нельзя использовать из двух мест одновременно.
5. **Флуд-контроль.** После нескольких запросов подряд Telegram выдаёт паузу;
   скрипт покажет её длительность в секундах.

## Структура

```
bot/
  main.py            # сборка приложения: Telethon, aiogram, роутеры слайсов
  core/              # общее: конфиг, состояние, логгер, доступ владельца, UI-помощники
  channels/          # слайс: список каналов
  message/           # слайс: текст рассылки
  interval/          # слайс: интервал
  broadcast/         # слайс: отправка, планировщик, старт/стоп
data/                # state.json и session.session (в git не попадают)
logs/                # bot.log
```

Каждый слайс самодостаточен: свои `handlers.py` и `service.py`.
